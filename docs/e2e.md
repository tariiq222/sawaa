# اختبارات سواء باستخدام TesterArmy e2e

هذه طبقة اختبارات رحلات مستخدم فوق الاختبارات الحالية. Playwright الموجود في لوحة التحكم يبقى بوابة smoke الرسمية، وJest للباك وVitest للواجهات يبقيان مسؤولين عن الاختبارات التفصيلية.

## النطاق الحالي

- `e2e.config.ts`: هدفا `website` و`dashboard`، عامل واحد افتراضيًا.
- `e2e/models.ts`: GPT-6.1 Sol فقط، للمنفذ والقاضي، عبر جلسة ChatGPT الخاصة بأداة e2e. لا مفاتيح API ولا مزود احتياطي ولا قراءة لمخازن اعتماد تطبيقات أخرى.
- `SW-W01`: ظهور الصفحة الرئيسية العربية، دون استدعاء نموذج.
- صفحة دخول لوحة التحكم: العنوان وحقل المعرّف.
- `SW-D01`: المعرّف ← اختيار كلمة المرور ← دخول الموظف ← صفحة الحجوزات ← إعادة التحميل مع استمرار الوصول، ثم الخروج ومنع الوصول إلى الحجوزات دون جلسة. يستخدم حساب اختبار يملك `booking:read` ولا يفرض OTP.
- `SW-W02`: الوكيل يفتح دليل العيادات من قائمة الموقع، ثم تأكيد مباشر للرابط والعنوان. اختبار منفصل يحمل وسم `agent`، ويحتاج جلسة ChatGPT.
- إعدادان منفصلان للحجز المحلي (`e2e.local.config.ts`) والتطبيق (`e2e.mobile.config.ts`)، لا يشملهما التشغيل الافتراضي. يغطيان الحجز عند المركز وربطه بالموظف، وعقد Native مع Moyasar Sandbox، وحجز iOS على محاكي مخصص. اقرأ [دليل التشغيل المعزول](testing/e2e-local-runbook.md) و[سجل السيناريوهات](testing/e2e-scenarios.md) للأدلة والحدود.

## المتطلبات

Node ^22.22.3 أو >=24.8.0 لتوافق محرك اختبار الجوال، واعتماديات المشروع المثبتة والمتوافقة مع ملف القفل. يجب تشغيل الباك والموقع واللوحة قبل الاختبارات؛ الإعداد الحالي لا يشغّل الخوادم تلقائيًا.

```bash
pnpm dev:backend
pnpm --dir apps/dashboard dev
pnpm --dir apps/website dev
```

نفّذ كل أمر خادم في طرفية مستقلة، وأعد استخدام الباك القائم إن كان يعمل. عناوين الاختبار الافتراضية محلية. تستخدم الاختبارات التي تنشئ بيانات لاحقًا قاعدة اختبار قابلة للاستبدال وبيانات صناعية؛ لا تشغّلها على قاعدة الإنتاج أو قاعدة مشتركة.

## التشغيل

```bash
# مجموعة سريعة مباشرة، بلا خطوات agent أو حاجة لجلسة ChatGPT
pnpm e2e:smoke

# مجموعة سريعة لواجهة واحدة
pnpm exec e2e run --target website --tag smoke --exclude-tag agent
pnpm exec e2e run --target dashboard --tag smoke --exclude-tag agent

# سرد الاختبارات دون تشغيل متصفح أو نموذج
pnpm exec e2e list

# كل اختبارات الأداة، بما فيها الوكيل
pnpm e2e
pnpm e2e:website
pnpm e2e:ta-dashboard

# بوابة Playwright الحالية، مستقلة عن TesterArmy
pnpm --filter=dashboard run e2e:smoke
```

عند تمرير الخيارات عبر pnpm لا تضف `--` زائدة: استخدم `pnpm e2e:smoke --target website`.
كل الاختبارات تُجمع لكل هدف؛ الاختبار الخاص بواجهة أخرى يُتخطّى مع سبب صريح. لا تعد هذه التخطيّات تغطية، ولا تعد الخروج برمز صفر وحده دليل قبول.

## الحسابات والبيئة

صدّر هذه المتغيرات في بيئة عملية الاختبار؛ لا يحمّل `e2e.config.ts` ملفات `.env` تلقائيًا:

| المتغير | الاستخدام |
|---|---|
| `E2E_WEBSITE_URL` | الافتراضي `http://localhost:5205` |
| `E2E_DASHBOARD_URL` | الافتراضي `http://localhost:5203` |
| `E2E_USER_DASHBOARD_USERNAME` | معرّف موظف الاختبار المخصص |
| `E2E_USER_DASHBOARD_PASSWORD` | كلمة مروره من مخزن الأسرار/بيئة التشغيل |

عند غياب أحد متغيري الحساب، يُتخطّى `SW-D01` مع السبب؛ هذا ليس نجاحًا للدخول. عند توفيرهما يستخدم الاختبار `credentials.user('dashboard')` ومقبض Secret عند ملء كلمة المرور. لا توجد بيانات دخول افتراضية في الحزمة، ولا يتجاوز الاختبار واجهة الدخول عبر حقن رموز أو cookies.

جلسة اشتراك ChatGPT مستقلة عن حساب موظف سواء:

```bash
pnpm exec e2e login openai
pnpm exec e2e models openai
```

تحقق من إتاحة `gpt-6.1-sol` قبل التشغيل الذكي. إذا غاب النموذج أو تسجيل الدخول، تتوقف خطوات الوكيل ويُبلّغ السبب؛ لا يُستبدل النموذج. اختبارات `smoke` المباشرة تستمر دون نموذج. حد الوكيل الحالي خمس استدعاءات لكل خطوة وبجهد `low`.

## النتائج والقبول

النتائج تحت `.e2e/` ومُتجاهلة في Git. استخدم مجلدًا مختلفًا للحفاظ على دليل تشغيل سابق:

```bash
pnpm e2e:smoke --output .e2e/phase1-smoke
```

اقرأ `report.json`، وعدد الاختبارات الناجحة والمتخطاة والفاشلة، وسبب كل تخطٍّ. الأسرار المسجلة محجوبة، وبعد ملء كلمة مرور عبر Secret تحجب الأداة صور الشاشة؛ لذلك لا يُشترط وجود لقطة لكل خطوة دخول.

خطوات `agent.act` المتحقق من نتائجها قد تُعاد من الكاش دون نموذج؛ `agent.assert` و`agent.waitFor` و`agent.extract` تبقى استدعاءات حية. استخدم التأكيدات المباشرة للمعرفات والمبالغ والحالات.

دليل محلي لا يثبت قبول staging أو جهاز فعلي. قبول Sandbox يخص المزود التجريبي والمسار المنفذ فقط. قبول الإصدار يبقى حسب [سياسة النشر](operations/deployment-policy.md)، بعد اختبارات staging وقبول المالك اليدوي.
