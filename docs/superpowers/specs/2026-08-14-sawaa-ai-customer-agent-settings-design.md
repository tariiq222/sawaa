# تصميم وكيل Sawaa Ai لخدمة العملاء والمبيعات

**التاريخ:** 2026-08-14
**الحالة:** معتمد في المحادثة، بانتظار مراجعة الوثيقة
**يعتمد على:** `2026-08-13-unified-web-ai-chat-design.md`
**يستبدل:** وصف «المساعد الإداري» وسياسة القوالب المغلقة في الأقسام 1 و8 و9 و11 و12 و15 من التصميم السابق

## 1. الهدف

تحويل `Sawaa Ai` من مصنف لعبارات إدارية وردود ثابتة إلى وكيل محادثة طبيعي لخدمة عملاء مركز سواء والمبيعات. يتحدث بلهجة سعودية خفيفة ومحترمة، يفهم سياق العميل، يشرح الخدمات، يعالج التردد والاعتراضات، ويرشد العميل تدريجيًا إلى الحجز أو التحويل لفريق الاستقبال.

يبقى الوكيل محصورًا في نطاق مركز سواء. لا يشخص، لا يقيّم الحالة، لا يقدم إرشادًا علاجيًا أو طبيًا، ولا يضمن نتائج. كل معلومة تشغيلية أو سعر أو موعد أو معالج تأتي من أدوات النظام أو قاعدة المعرفة المنشورة، وليست من ذاكرة النموذج.

## 2. القرارات المعتمدة

- يقبل التحيات والمجاملات والحديث القصير مثل «كيف حالك؟»، «شكرًا»، و«مع السلامة» ويرد طبيعيًا.
- يفهم العربية العامية واللهجة السعودية ولا يشترط صياغة مطابقة لقالب.
- يسأل سؤالًا واحدًا مناسبًا في كل مرة بدل استبيان طويل.
- يسأل أسئلة خدمية غير سريرية لتحديد الخدمة أو المعالج أو الموعد المناسب.
- يرشح خيارات بناءً على تفضيلات العميل المعلنة، لا على تشخيص أو استنتاج نفسي.
- يعالج اعتراض السعر باستخدام الأسعار والبدائل الحقيقية فقط؛ لا يخترع خصمًا ولا يضغط على العميل.
- يقود العميل للحجز، لكن تسجيل الدخول والتأكيد مطلوبان قبل أي حجز أو تعديل أو إلغاء.
- إذا وجد حجزًا مستقبليًا فعالًا، يعرضه ويطلب إقرارًا إضافيًا قبل موعد آخر، مع منع التطابق والتعارض.
- يحوّل للاستقبال بطلب العميل أو عند نقص معلومة موثوقة أو عدم توفر موعد أو وجود شكوى أو استثناء مالي.
- قبل التحويل يجمع التفاصيل اللازمة حسب نوع الطلب. الضيف يقدم الاسم والجوال.
- لا يسأل عن وقت أو وسيلة التواصل؛ يخبر العميل أن فريق الاستقبال سيتواصل خلال أوقات عمل المركز.
- إعداد مزود الذكاء وقاعدة المعرفة يظهران في صفحة إعدادات مستقلة باسم `Sawaa Ai`.
- يدعم الإصدار الأول `OpenRouter` و`OpenAI`.
- تنظف بقايا واتساب بأمان دون حذف أعمى للبيانات أو الجداول أو migrations التاريخية.

## 3. شخصية الوكيل وأسلوبه

اسم الوكيل الظاهر والداخلي هو `Sawaa Ai Customer Agent`، والاسم المعروض للعميل `Sawaa Ai`.

قواعد الأسلوب:

- العربية الافتراضية لهجة سعودية خفيفة: «أبشر»، «حياك الله»، «خلني أساعدك» عند ملاءمتها للسياق.
- لغة محترمة، هادئة، غير متكلفة، ولا تستخدم عامية مبالغًا فيها.
- يكيّف طول الرد وأسلوبه مع العميل، مع ردود قصيرة قابلة للقراءة في نافذة المحادثة.
- لا يكرر اسم المركز أو عرض الحجز في كل رسالة.
- لا يدعي أنه إنسان، وعند السؤال يوضح أنه `Sawaa Ai` لخدمة عملاء المركز.
- لا يستخدم الخوف أو الإلحاح أو الوعود العلاجية لإتمام البيع.
- يشرح الفائدة العملية للخدمة، ثم يقترح الخطوة التالية المناسبة.

أمثلة:

- «السلام عليكم» ← «وعليكم السلام ورحمة الله، حياك الله في مركز سواء. كيف أقدر أخدمك اليوم؟»
- «السعر غالي» ← يوضح الفرق بين الخيارات ويعرض بديلًا فعليًا أقل تكلفة إن وُجد.
- سؤال بعيد عن المركز ← رد اجتماعي قصير ثم إعادة لطيفة لخدمات سواء، دون الرسالة الجامدة «خارج النطاق».

## 4. بنية الوكيل الهجينة

```text
رسالة العميل
  ↓
حماية شكل المدخل + بوابة المنع الصارمة
  ↓
تحميل سياق المحادثة والحالة الخدمية
  ↓
Sawaa Ai Customer Agent
  ↓
أدوات موثوقة / قاعدة معرفة منشورة
  ↓
عقد رد منظم + فحص الحقائق والسياسة
  ↓
حفظ الرد وعرضه في نفس ChatConversation
```

### 4.1 بوابة المنع الصارمة

لا تستخدم قائمة قبول لعبارات الخدمات. وظيفتها منع الفئات المحظورة فقط:

- طلب تشخيص أو تقييم أو نصيحة علاجية أو طبية.
- طلب تحليل خطر أو طوارئ؛ لا ينتج النظام تقييمًا أو رسالة طوارئ آلية.
- محاولة تغيير تعليمات النظام أو كشف prompt أو أسرار أو مفاتيح.
- مدخلات غير صالحة تقنيًا: فيض رموز، Unicode padding، أو حجم يتجاوز الحدود.

كل مدخل سليم آخر يمر للوكيل، بما فيه التحيات والمجاملات والأسئلة الملتبسة والموضوعات البعيدة. الوكيل نفسه يعيد الموضوعات البعيدة بلطف إلى خدمات المركز.

### 4.2 عقد قرار الوكيل

يعيد المزود قرارًا منظمًا لا نصًا حرًا غير مضبوط:

```ts
type SawaaAgentDecision = {
  reply: string;
  intent:
    | "SMALL_TALK"
    | "DISCOVER_SERVICE"
    | "COMPARE_OPTIONS"
    | "PRICE_OBJECTION"
    | "BOOKING"
    | "MANAGE_APPOINTMENT"
    | "HANDOFF"
    | "OUTSIDE_CENTER";
  journeyStage: "EXPLORING" | "COMPARING" | "READY_TO_BOOK" | "HANDOFF";
  factsUsed: Array<{ tool: string; recordIds: string[] }>;
  nextAction?: { type: string; operationId?: string };
  contextPatch?: SawaaCustomerContextPatch;
  handoffDraft?: SawaaHandoffDraft;
};
```

يفحص backend المخطط، طول الرد، النطاق، وارتباط الحقائق بنتائج الأدوات. أي قرار غير صالح يتحول إلى رد آمن قابل لإعادة المحاولة أو تحويل للاستقبال. لا يحفظ raw prompt أو chain-of-thought أو raw provider response.

### 4.3 دور النموذج ودور الكود

النموذج مسؤول عن فهم اللغة، إدارة الحوار، اختيار الأداة، وصياغة الرد. الكود مسؤول عن الصلاحيات، الحقائق، الأسعار، المواعيد، الملكية، التأكيد، الحجز، الحدود، ومنع التكرار. لا يملك النموذج أداة تنفيذ مباشر لأي عملية حساسة.

## 5. ذاكرة رحلة العميل

تضاف حالة خدمية منظمة إلى `ChatConversation` أو نموذج تابع لها عبر migration إضافية:

```ts
type SawaaCustomerContext = {
  journeyStage: "EXPLORING" | "COMPARING" | "READY_TO_BOOK" | "HANDOFF";
  serviceInterestIds: string[];
  practitionerPreferenceIds: string[];
  modality?: "IN_PERSON" | "ONLINE";
  preferredDays?: string[];
  preferredTimeWindow?: string;
  budgetConcern?: boolean;
  selectedServiceId?: string;
  selectedPractitionerId?: string;
};
```

لا تحفظ الحالة أعراضًا أو تشخيصًا أو تقييمًا نفسيًا أو استنتاجات سريرية. لا يعتمد الوصول أو الحجز على قيم يولدها النموذج؛ يعيد backend التحقق من كل معرّف وقيمة.

## 6. أدوات Sawaa Ai

### 6.1 أدوات عامة

- `getCenterInfo`
- `listServices`
- `getServiceDetails`
- `compareServices`
- `listPractitioners`
- `getPractitionerDetails`
- `getAvailability`
- `searchPublishedKnowledge`
- `prepareReceptionHandoff`

`compareServices` ونتائج الترشيح ترتب البيانات المنشورة بناءً على تفضيلات خدمية صريحة مثل النوع والسعر والحضور، ولا تستخدم أعراضًا أو استدلالًا سريريًا.

### 6.2 أدوات العميل المسجل

- `listOwnAppointments`
- `prepareBooking`
- `prepareReschedule`
- `prepareCancellation`

لا توجد أداة `confirm` أو أداة تنفيذ حر. تعرض الواجهة بطاقة حتمية ويؤكد العميل عبر endpoint يقرأ العملية المحفوظة ويعيد التحقق داخل transaction.

### 6.3 قواعد الأدوات

- `clientId` يأتي من جلسة backend ولا يقبله النموذج أو المتصفح.
- كل النتائج إسقاطات محدودة لا تتضمن أسرارًا أو هوية داخلية.
- حد أقصى لأربع دورات أدوات وثماني استدعاءات في الرسالة.
- لا يستخدم أي سعر أو موعد أو اسم معالج لم يعد في نتيجة أداة حديثة.
- فشل الأداة يمنع التخمين ويعرض إعادة المحاولة أو الاستقبال.

## 7. رحلة الخدمة والمبيعات

1. **ترحيب وفهم أولي:** رد طبيعي وسؤال واحد عن المطلوب.
2. **استكشاف:** أسئلة غير سريرية عن نوع الخدمة، حضوري/عن بُعد، الوقت، أو تفضيل المعالج.
3. **ترشيح:** خياران أو ثلاثة من بيانات المركز مع شرح مختصر للفروق.
4. **اعتراضات:** توضيح القيمة والبدائل الفعلية دون خصومات مختلقة أو ضغط.
5. **نية الحجز:** تحديد الخدمة والمعالج والوقت.
6. **الهوية:** تسجيل الدخول عند بدء عملية شخصية فقط.
7. **التحقق:** عرض أي حجز قائم ومنع التعارض أو التكرار.
8. **التأكيد:** بطاقة واضحة، ثم تنفيذ idempotent.
9. **النتيجة:** رسالة نجاح أو سبب فشل قابل للتصرف.

## 8. التحويل للاستقبال

أسباب التحويل:

- طلب العميل.
- عدم وجود معلومة موثوقة بعد محاولة مناسبة.
- عدم توفر موعد مناسب.
- شكوى.
- استثناء مالي أو طلب خصم غير منشور.
- فشل متكرر للمزود أو أداة لازمة.

يجمع الوكيل حسب الحالة: موضوع الطلب، التفاصيل التي حدثت، النتيجة المطلوبة، الخدمة أو المعالج، والبدائل المقبولة. الضيف يضيف الاسم والجوال. لا يطلب وقتًا أو قناة للتواصل.

يحفظ backend ملخصًا خَدَميًا منظمًا بلا تحليل سريري، ويعرضه مع كامل السجل في صندوق الاستقبال. الرد النهائي:

> تم استلام طلبك وتحويله لفريق الاستقبال، وبيتواصلون معك خلال أوقات عمل المركز.

## 9. إعدادات Sawaa Ai في الداشبورد

يستبدل تبويب `whatsapp` في `/settings` بتبويب `sawaa-ai`، ويحتوي على ثلاثة أقسام:

### 9.1 التكامل

- المزود: `OPENROUTER` أو `OPENAI`.
- مفتاح API write-only ومشفّر بـAES-256-GCM باستخدام خدمة credentials عامة و`DEFAULT_ORG_ID` كـAAD وفق نمط المشروع.
- model مع قائمة نماذج متاحة أو إدخال مقيد.
- base URL ثابت لكل مزود؛ لا يسمح للمستخدم بإدخال عنوان اعتباطي في الإصدار الأول لتجنب SSRF.
- temperature وmax output tokens ضمن حدود backend.
- زر «اختبار الاتصال» ينفذ طلبًا صغيرًا ولا يحفظ المفتاح إلا بعد نجاح الاختبار والتأكيد.
- حالة: غير مهيأ، متصل، فشل الاختبار، أو يحتاج إعادة اختبار.
- `lastTestedAt` ورسالة خطأ آمنة بلا أسرار.
- مفتاح التفعيل لا يفتح الخدمة للعامة إلا بعد نجاح اختبار المزود.

### 9.2 شخصية الوكيل

- تفعيل أو تعطيل `Sawaa Ai`.
- اللغة الافتراضية.
- نص الترحيب العربي والإنجليزي ضمن حدود آمنة.
- نبرة سعودية خفيفة ثابتة لا يمكن للإعداد تعطيل حدود النظام.
- لا يسمح prompt مخصص باستبدال سياسة الأمان أو توسيع الأدوات.

### 9.3 قاعدة المعرفة

- قائمة الوثائق مع بحث وحالة وفلاتر وتاريخ آخر فهرسة.
- إنشاء إدخال يدوي بعنوان ومحتوى.
- إضافة مصدر URL موثوق عند اعتماد allowlist للنطاقات.
- تعديل، مسودة، نشر، إلغاء نشر، حذف، وإعادة فهرسة.
- معاينة المقاطع التي سيبحث فيها الوكيل دون عرض embedding الخام.
- لا يستخدم الوكيل إلا الوثائق المنشورة والمفهرسة بنجاح.
- فشل الفهرسة ظاهر للمشرف ولا يجعل الوثيقة متاحة للوكيل.

يعاد استخدام `KnowledgeDocument`, `DocumentChunk`, `SemanticSearchHandler` والواجهة الحالية بعد تصحيح عقودها وإكمال create/publish/reindex. لا ينشأ مخزن معرفة موازٍ.

## 10. عقد البيانات والإعدادات

يضاف نموذج عام مستقل عن واتساب، باسم مكافئ لـ`AiProviderConfig`:

```prisma
enum AiProvider {
  OPENROUTER
  OPENAI
}

enum AiConnectionStatus {
  NOT_CONFIGURED
  CONNECTED
  FAILED
  RETEST_REQUIRED
}

model AiProviderConfig {
  id                   String             @id @default(uuid())
  provider             AiProvider
  credentialCiphertext String
  model                String
  temperature          Float              @default(0.4)
  maxTokens            Int                @default(800)
  isEnabled            Boolean            @default(false)
  connectionStatus     AiConnectionStatus @default(NOT_CONFIGURED)
  lastTestedAt         DateTime?
  lastTestOk           Boolean?
  lastTestErrorCode    String?
  createdAt            DateTime           @default(now())
  updatedAt            DateTime           @updatedAt
}
```

الاستجابة العامة لا تعيد `credentialCiphertext` أو جزءًا من المفتاح. تعرض فقط `hasCredential: true/false`.

يمدد `DocumentStatus` بقيم واضحة للمسودة والنشر والفهرسة عبر migration إضافية، أو يضاف حقل نشر مستقل إذا كان أقل خطرًا على التوافق. لا تعدل أي migration سابقة.

## 12. جاهزية المزود والأخطاء

- لا تعتبر الخدمة جاهزة إذا لم يوجد config فعال واتصال ناجح حديثًا.
- `WEB_CHAT_ENABLED` لا يكفي وحده؛ يلزم `AiProviderConfig.isEnabled` و`connectionStatus=CONNECTED`.
- عند بدء backend يتحقق من قابلية فك المفتاح وبنية الإعداد، ولا يرسل المفتاح إلى logs.
- عند 401/403 يتحول config إلى `RETEST_REQUIRED` وتظهر الحالة للمشرف.
- timeout و5xx ينتجان retry محدودًا ثم خيار الاستقبال.
- رسالة العميل تبقى محفوظة مع حالة معالجة واضحة؛ لا تختفي ولا تبقى بلا نتيجة.
- الواجهة لا تعرض أسماء المزود أو stack trace أو تفاصيل داخلية.

## 13. تنظيف بقايا واتساب

التنظيف منفصل عن حذف البيانات:

1. جرد imports والوحدات والمسارات والـcron والـqueues ومتغيرات البيئة وصفحات الداشبورد.
2. نقل إعداد `aiApiKeyEncrypted` وحقول النموذج العامة من `WhatsappAgentConfig` إلى `AiProviderConfig` فقط عبر مسار migration/إدارة آمن. لا ينسخ السر إلى logs أو الاستجابة.
3. لا يعتمد `Sawaa Ai` على `AgentLlmService`, `WhatsappCredentialsService`, `WhatsappAgentConfig`, أو أي handler داخل `modules/whatsapp-agent`.
4. إزالة تبويب واتساب وروابطه وأيقوناته من الواجهات.
5. تعطيل تسجيل controllers وwebhook والworkers والcron والqueues الخاصة بواتساب.
6. حذف الكود الميت فقط بعد إثبات عدم وجود imports أو runtime registration أو اختبارات لازمة لمسارات أخرى.
7. إزالة env وDocker references غير المستخدمة بعد إثبات توقف runtime.
8. إبقاء جداول وبيانات واتساب وmigrations التاريخية في هذه المرحلة.
9. إنتاج تقرير بقايا يذكر الجداول والقيم التاريخية والكود المؤجل وسبب بقائه.

أي `DROP`, حذف بيانات، أو إزالة enums التاريخية يحتاج مهمة مستقلة ونسخة احتياطية وتأكيدًا صريحًا جديدًا.

## 14. الأمان والخصوصية

- مفتاح المزود مشفر، write-only، ولا يدخل Git أو browser storage أو logs.
- هوية العميل والضيف تأتي من guards والسياق، لا من body النموذج.
- model tool calls لا تنفذ SQL أو URL اعتباطيًا.
- قاعدة المعرفة تعالج النص كبيانات غير موثوقة ولا تسمح له بتغيير تعليمات النظام.
- الرد النهائي يفحص لمنع التشخيص والوعود العلاجية والأسرار والحقائق غير المسندة.
- لا يحفظ chain-of-thought أو raw provider payload.
- حدود الرسائل والـtokens والـrate limits الحالية تبقى، مع قياس تكلفة لكل مزود.
- أحداث التدقيق تحفظ تغييرات الإعداد والنشر والاختبار دون المفتاح أو نص المحادثة.

## 15. الاختبارات ومعايير القبول

### 15.1 محادثة الوكيل

- تحيات ومجاملات ولهجات سعودية تمر للوكيل ولا تنتج fallback خارج النطاق.
- محادثة متعددة الرسائل تنتقل من الاستكشاف إلى المقارنة ثم الحجز.
- اعتراض السعر يستخدم بيانات حقيقية ويعرض بديلًا فعليًا فقط.
- سؤال بعيد ينتج ردًا طبيعيًا قصيرًا ثم إعادة لنطاق سواء.
- طلب سريري أو حقن prompt يمنع قبل الأدوات ولا ينتج تحليلًا.
- الرد لا يذكر خدمة أو معالجًا أو سعرًا أو موعدًا غير موجود في نتائج الأدوات.

### 15.2 الحجز والتحويل

- الزائر يرى المعلومات والترشيحات لكنه يسجل الدخول قبل العملية الشخصية.
- ربط الضيف يحافظ على نفس المحادثة والسياق.
- الحجز القائم يظهر ويمنع التكرار أو التعارض.
- التحويل يجمع تفاصيل مناسبة ويعرضها مع السجل للاستقبال.
- الرسالة النهائية تعد بالتواصل خلال أوقات العمل فقط.

### 15.3 الإعدادات والمعرفة

- مفتاح المزود لا يظهر في GET أو OpenAPI examples أو logs.
- OpenRouter وOpenAI ينجحان في controlled integration test بمفاتيح اختبار يضعها المشغل.
- مفتاح غير صالح ينتج حالة `RETEST_REQUIRED` ولا يترك الخدمة تبدو متصلة.
- المسودة أو الوثيقة الفاشلة لا تظهر في RAG.
- النشر وإعادة الفهرسة ينعكسان على نتائج البحث بعد اكتمال worker.
- صلاحيات القراءة والتعديل مطبقة في backend والواجهة.

### 15.4 التكامل الحقيقي

- Postgres وRedis وBullMQ ومزود اختبار فعلي.
- الموقع: إرسال تحية ثم استلام رد طبيعي.
- رحلة خدمة حتى بطاقة حجز وتأكيد.
- فشل مزود ثم retry وتحويل للاستقبال.
- الداشبورد: حفظ إعداد، اختبار اتصال، نشر معرفة، ورؤية محادثة محولة.
- OpenAPI snapshot وأنواع الداشبورد متطابقة مع runtime.

## 16. الإطلاق والرجوع

1. إضافة schema والإعدادات خلف flags مغلقة.
2. نقل أو إدخال مفتاح المزود من صفحة الإعدادات واختبار الاتصال.
3. نشر قاعدة معرفة أولية واعتماد نتائج البحث.
4. تشغيل corpus واختبارات التكامل ثم تجربة داخلية.
5. تفعيل `Sawaa Ai` للعامة بعد اتصال أخضر فقط.
6. تعطيل runtime واتساب وإزالة أسطحه الظاهرة.
7. مراقبة الأخطاء والتكلفة والتحويل للحجز والاستقبال.

الرجوع يغلق `AiProviderConfig.isEnabled` وfeature flags دون حذف المحادثات أو المعرفة أو الإعداد المشفر. تنظيف واتساب لا يتضمن حذف بيانات، لذلك يمكن إعادة التسجيل مؤقتًا من الصورة السابقة إذا لزم قبل مهمة الحذف المستقلة.

## 17. خارج النطاق

- تشخيص أو تقييم أو علاج أو طوارئ.
- خصومات يولدها الوكيل أو تفاوض مالي غير معتمد.
- تنفيذ حجز دون تسجيل دخول وتأكيد.
- أدوات عامة للويب أو الطقس أو الأخبار.
- fine-tuning في الإصدار الأول.
- حذف جداول أو بيانات أو migrations واتساب ضمن مهمة التنظيف.
- إدخال مفتاح مزود بواسطة وكيل برمجي؛ المشغل يدخله بنفسه من صفحة الإعدادات.
