## النسخ الاحتياطية والرجوع

- إنتاج OpenShip: شوهد ملف `sawaa-production-current.tar.gz.age` على الخادم بتاريخ تعديل 24 سبتمبر 02:16 بتوقيت الخادم. هذا يثبت وجود الملف وحداثته فقط. نجاح الرفع الخارجي وآخر تمرين استعادة إنتاج يحتاجان تحديثًا مستقلًا؛ لا تنقل دليل تجربة قديمة إليهما.
- التجربة اليدوية المحذوفة: أرشيف مشفّر على الخادم في `/var/backups/webvue/sawaa-legacy-retirement-20260924/` ونسخة محلية خاصة. تطابقت بصمة النقل؛ استُعيدت نسخة PostgreSQL المنطقية من الأرشيف داخل حاوية `network=none` بلا منافذ، وتطابقت 92 جدولًا. هذه نسخة البيئة المحذوفة، وليست نسخة الإنتاج. تقرير الحذف محفوظ لدى المشغّل خارج Git.
- [دليل الاستعادة](restore-runbook.md) يتضمن إعداد Compose القديم؛ وجوده لا يثبت أن جدوله يعمل على OpenShip. يلزم مطابقة المجدول والوجهة ووقت آخر نجاح/استعادة مع بيئة الإنتاج الفعلية.
- الرجوع للكود يتطلب تحديد نشر وصور سابقة متوافقة مع قاعدة البيانات الحالية. وسم rollback وحده لا يثبت توفر الصور أو صلاحية استعادة البيانات.

## الحماية والفجوات المفتوحة

- آخر فحص GitHub في 24 سبتمبر: `main` و`develop` كلاهما `protected=false`، وعدد GitHub Environments صفر؛ طلب الحماية/rulesets أعاد 403 متعلقًا بخطة الحساب. لم تُغيّر الخطة أو الحماية في هذه المهمة.
- بعد معالجة قيد الخطة، تُفرض PRs والفحوص المطلوبة دون تجاوز، وتُراجع آلية قبول الإنتاج وصلاحيات OpenShip. نجاح workflow لا يعوّض حماية الفرع أو موافقة المالك.
- لا توجد إيصالات نشر جديدة مستوفية [لعقد التسجيل](deployments/README.md) بعد. معرفات النشر والصحة أعلاه أدلة جزئية؛ لا تُختلق قيمة SHA مفقودة لتمرير التسجيل.
- `.github/DEPLOY_STATE.json` القديم متقاعد. GitHub Releases تصف إصدارات الكود، وسجلات `deployments/` تصف ملاحظات تشغيل محددة بتاريخها.
- ملف `apps/mobile/credentials.json` مستثنى في هذا الفرع، وأضيف استثناء محلي إلى `info/exclude` في النسخة الأصلية لحمايته قبل الدمج. الاستثناء المحلي لا ينتقل إلى نسخ المستودع الأخرى، والاستثناء عمومًا لا يسحب سرًا سبق رفعه.
