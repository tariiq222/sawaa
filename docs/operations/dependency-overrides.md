# سجل تجاوزات الاعتماديات (pnpm overrides)

> **الغرض:** لكل `pnpm.overrides` سبب مكتوب وتاريخ إدخال فعلي، كما تطلب MNT-26.
> **متى يُحدَّث:** عند إضافة أو حذف أو تغيير أي override.
> **التواريخ** محسوبة من تاريخ git: أول commit تكون فيه هذه القيمة الدقيقة داخل كتلة `pnpm.overrides`، لا أول ذكر للاسم في الملف.

## 1. الخلفية والخطورة

`pnpm.overrides` يفرض إصدارًا واحدًا على كل شجرة الاعتماديات. أداة قوية لكنها تُفشل أداة كاملة بصمت عند فرض إصدار غير متوافق. حدث ذلك فعلًا في MNT-27:

| التجاوز المرفوض | ما كسره | الدليل |
|---|---|---|
| `glob@14` عالميًا | Jest 29 | `glob.sync` محذوف |
| `minimatch@11` | ESLint 9 | `expand is not a function` عبر `brace-expansion@5` |
| `decode-uri-component@0.5.1` | MinIO + روابط الجوال | ESM مقابل CommonJS |
| `stream-json@3.x` | MinIO | `.make()` غير متاح |
| `zod@4` على كل النسخ | `shadcn` | يعتمد zod 3 |

لذلك كل صف مُصنَّف، والمثبّتات لها سبب يمنع رفعها بلا إعادة اختبار.

## 4. مراجعة كل ربع

1. **الأمني:** إن صدر إصدار يسمح بالحذف، احذف التجاوز بدل تثبيته.
2. **المثبّت:** أعد اختبار الكسر الموثق قبل أي رفع. البيئات الأربع الحساسة:
   MinIO (`query-string`/`stream-json`)، فك روابط الجوال، ESLint، Jest.
3. **التوافق:** تأكد أن React والأنواع نسخة واحدة فعلًا (`pnpm why react`).
4. **`.trivyignore.yaml`:** كل استثناء له `expired_at` وسبب وصول مكتوب.
5. **قاعدة جديدة:** لا يُضاف override بلا صف هنا. راجع `docs/plans/maintainability-roadmap.md` (MNT-26).
